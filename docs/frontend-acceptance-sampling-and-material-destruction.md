# 前端改造指导：验收取样扣减 + 物料销毁记录

> 对应后端改动：`验收入库按取样数量扣减 + 物料销毁记录`
> 影响页面：货物验收（验收单列表/详情/新增编辑/检验/入库/导出）、销毁记录（新增类型与明细字段/列表筛选）

---

## 一、总体变化

| 模块 | 变化 |
|---|---|
| 验收明细 | 新增 `samplingQty`（取样数量）；`inboundQty` 改为**服务端计算、只读** |
| 验收入库 | 入库数量 = 实际到货数量（未填时回退采购数量）− 取样数量 |
| 验收导出 | 货物验收表由 24 列扩为 25 列，新增取样数量 |
| 销毁记录 | 新增记录类型「物料销毁」，单号前缀 `WLXH`；明细新增 `itemCategory`（品名类别）、`unitName`（计量单位） |

---

## 二、货物验收模块

### 2.1 明细字段（请求/响应通用）

`AcceptanceDetail` 新增字段（JSON 为 camelCase）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `samplingQty` | number \| null | 取样数量，空按 0 处理，不可为负；入库时按该数量扣减 |
| `inboundQty` | number \| null | 入库数量，**只读**，由服务端计算并返回；前端提交该字段会被忽略 |

页面展示建议在验收明细表格中增加两列：**取样数量、入库数量**，其中入库数量只读展示。

### 2.2 新增验收单 / 编辑明细

接口不变：

- 新增：`POST /api/acceptance/withDetails`
- 批量更新明细：`PUT /api/acceptance/detail`

新增请求示例：

```json
{
  "acceptance": { "sourceType": "采购入库", "relatedOrder": "DD-20260723-001" },
  "details": [
    {
      "materialCode": "Y0084",
      "materialName": "甘草",
      "materialCategory": "原料",
      "unitName": "kg",
      "standardDosage": 0.021,
      "quantity": 0.42,
      "actualArrivalQty": 0.40,
      "samplingQty": 0.02,
      "unitPrice": 30,
      "batchNumber": "HG20260723",
      "expiryDate": "2027-07-23"
    }
  ]
}
```

批量更新明细示例：

```json
[
  { "detailId": 1, "batchNumber": "HG20260723", "unitPrice": 30 },
  { "detailId": 2, "actualArrivalQty": 0.40, "samplingQty": 0.02, "batchNumber": "HG20260724" }
]
```

表单交互建议：

1. 取样数量默认 0，允许为空（后端按 0 处理）。
2. 输入时实时提示「入库数量 = 实际到货数量（未填则用采购数量）− 取样数量」，并展示计算后的预计入库数量。
3. 前端可做即时校验：取样 ≥ 0；取样数量 ≤ 基准数量；检验合格/入库前要求取样数量 **< 基准数量**（保证入库数量 > 0）。
4. 明细已进入 `待扫码入库`/`已入库` 时，取样数量、批号、单价、仓库均不可再编辑。

### 2.3 验收流程环节

| 环节 | 接口 | 前端注意事项 |
|---|---|---|
| 初验 | `POST /api/acceptance/{id}/inspect` | 合格后不强制校验取样数量；不合格转退货时后端自动把入库数量清零 |
| 检验 | `POST /api/acceptance/{id}/quality-check` | 合格前要求批号必填，且取样数量 < 基准数量；不满足会返回明确错误 |
| 整单入库 | `POST /api/acceptance/{id}/inbound` | 入库单数量按扣减后的入库数量生成；此时验收单/明细为 `待扫码入库`，不是 `已入库` |
| PDA 确认 | 扫码签名确认后 | 后端回写验收单与明细为 `已入库` |
| 部分验收 | `POST /api/acceptance/{id}/partial-acceptance` | 验收子行保留取样；退货子行取样与入库数量均为 0；取样数量超过验收数量会被拒绝 |

状态提示：`inbound` 返回后主单状态为 **待扫码入库**，请在前端按两阶段流程展示，不要再直接把状态改为「已入库」。

### 2.4 常见错误提示（建议直接弹出后端 message）

| 后端提示 | 触发场景 |
|---|---|
| `取样数量不能为负数: X` | 取样数量 < 0 |
| `取样数量不能超过入库基准数量: X` | 取样数量 > 实际到货（或采购）数量 |
| `取样数量不能等于入库基准数量，入库数量必须大于0: X` | 检验合格时取样数量等于基准数量 |
| `入库数量必须大于0，请检查取样数量: X` | 入库时数量为 0 |
| `已生成入库单或已入库的验收单不可修改/删除` | 主单处于待扫码入库/已入库 |
| `已生成入库单或已入库的明细不可删除` | 明细处于待扫码入库/已入库 |

### 2.5 导出

接口：`GET /api/purchase-orders/annual-statistics/export`

列顺序（25 列）：

```
验收单号、来源类型、关联采购订单号、关联采购计划编号、收货单位、状态、交期、备注、
序号、物料编码、物料名称、物料分类、单位、采购数量、到货数量、取样数量、入库数量、
单价、金额、批号、有效期至、明细状态、退货原因、不合格说明、供应商
```

如果前端有导入模板或列映射配置，需要同步新增「取样数量」一列。

## 三、销毁记录模块

### 3.1 记录类型

记录类型下拉新增一项：

| 显示名 | `recordType` 值 | 单号前缀 |
|---|---|---|
| 不合格品销毁 | `不合格品销毁` | `BPXH-` |
| 留样及稳定性考察产品销毁 | `留样及稳定性考察产品销毁` | `LYXH-` |
| 物料销毁 | `物料销毁` | `WLXH-` |

选择「物料销毁」时：

- 明细表显示 **品名类别**、**计量单位** 两列/字段；
- 隐藏或禁用「关联留样」选择（该类型不允许携带 `retainedSampleId`）；
- 数量必须大于 0（其他类型仍允许空/0）。

品名类别取值（沿用质量模块术语）：

| 显示名（建议） | 提交值 |
|---|---|
| 原辅包 | `生产原料` |
| 中间品 | `中间产品` |
| 成品 | `成品` |

> 若产品页希望显示「原辅包/中间品/成品」，前端做显示映射即可，提交值必须用上表右侧值。

### 3.2 新增 / 修改销毁记录

- 新增：`POST /api/destruction`
- 修改：`PUT /api/destruction/{id}`（明细整体重建，**必须回传每行的 `itemCategory`、`unitName`**）
- 作废：`PUT /api/destruction/{id}/void`（作废后禁止修改）

物料销毁请求示例：

```json
{
  "recordType": "物料销毁",
  "destroyReason": "过期报废",
  "destroyMethod": "交有资质单位高温焚烧",
  "destroyLocation": "厂区危废暂存间",
  "applicantName": "李四",
  "applyDate": "2026-11-24",
  "approverName": "王五",
  "approveDate": "2026-11-24",
  "destroyerName": "赵六",
  "destroyDate": "2026-11-25",
  "supervisorName": "钱七",
  "superviseDate": "2026-11-25",
  "details": [
    { "materialName": "维生素C", "spec": "食品级", "batchNo": "20260701", "quantity": 50.5,
      "itemCategory": "生产原料", "unitName": "kg" },
    { "materialName": "复方制剂A", "spec": "10ml/支", "batchNo": "20260615", "quantity": 30,
      "itemCategory": "中间产品", "unitName": "L" },
    { "materialName": "感冒灵胶囊", "spec": "0.5g/粒", "batchNo": "20260610", "quantity": 10,
      "itemCategory": "成品", "unitName": "盒" }
  ],
  "attachmentFileIds": [201]
}
```

字段说明：

| 字段 | 必填（物料销毁） | 说明 |
|---|---|---|
| `recordType` | 是 | 固定 `物料销毁` |
| `details[].materialName` | 是 | 品名，≤100 字符 |
| `details[].quantity` | 是 | 必须 > 0 |
| `details[].itemCategory` | 是 | `生产原料` / `中间产品` / `成品` |
| `details[].unitName` | 是 | 计量单位，≤20 字符 |
| `details[].retainedSampleId` | 禁止 | 物料销毁不允许关联留样 |
| `totalQuantity` | 否 | 服务端按明细求和，前端不要提交 |
| `destructionCode` | 否 | 服务端自动生成，前端不要提交 |

### 3.3 单号与查询

- 获取单号：`GET /api/destruction/generateCode?recordType=物料销毁`，返回 `WLXH-YYYYMMDD-NNN`。
- 列表：`GET /api/destruction?recordType=物料销毁&itemCategory=成品&keyword=WL&status=正常&pageIndex=0&pageSize=10`
  - 新增可选参数 `itemCategory`，用于按品名类别筛选（精确匹配）。
- 详情：`GET /api/destruction/{id}`，明细行返回 `itemCategory`、`unitName`；附件接口 `GET /api/destruction/{id}/attachments` 不变。

列表页建议增加「品名类别」筛选下拉，仅在记录类型选择「物料销毁」或「全部」时展示。

### 3.4 表单校验提示

| 后端提示 | 触发场景 |
|---|---|
| `物料销毁明细数量必须大于0: X` | 数量为空或 ≤ 0 |
| `物料销毁明细品名类别必填: X` | 未选品名类别 |
| `品名类别只能是生产原料/中间产品/成品: X` | 类别值非法 |
| `物料销毁明细计量单位必填: X` | 未填单位 |
| `物料销毁不允许关联留样记录: X` | 携带了 `retainedSampleId` |

## 四、兼容与注意事项

1. **`inboundQty` 只读**：前端表单不要再提供「入库数量」输入框，统一展示服务端返回值；如需展示预计入库数量，按「基准数量 − 取样数量」前端实时计算后展示即可。
2. **历史数据**：旧验收单的取样为空，按 0 展示；旧销毁明细的品名类别/单位为空，正常展示为空即可。
3. **销毁明细整体重建**：编辑保存时必须回传全部明细字段（含 `itemCategory`、`unitName`），否则新类型校验会失败。
4. **库存与金额口径**：验收金额仍按到货数量计算；库存和入库单金额按扣减后的入库数量计算，两者差异属于正常现象（样品不进入库存）。
5. **接口鉴权与响应**：沿用现有 JWT 与 `ApiResponse` 结构，无新增鉴权要求。
