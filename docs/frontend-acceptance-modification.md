# 前端修改指导：货物验收取样数量与入库数量

> 适用范围：货物验收模块（验收单列表 / 详情 / 新增编辑 / 初验 / 检验 / 入库 / 导出）
> 本文只涉及货物验收，不含销毁记录。

---

## 一、数据口径

验收单包含多个物料行，取样数量与入库数量都按**明细行**（`acceptance_detail`）保存和计算，主单不保存数量。

| 字段 | 类型 | 前端处理 |
|---|---|---|
| `samplingQty` | number \| null | 可编辑，取样数量，默认 0/空 |
| `inboundQty` | number \| null | **只读**，服务端计算并返回，前端提交会被忽略 |

计算规则：

```
基准数量 = actualArrivalQty（未填时用 quantity）
入库数量 = 基准数量 − samplingQty（空按 0）
```

说明：

- 验收金额仍按实际到货数量 × 单价计算，取样不影响采购金额；
- 入库数量与库存金额按扣减后的数量计算，样品不进入库存；
- 取样数量目前为**手工录入**，不与请检/检验/取样记录模块关联。

## 二、页面改造

### 2.1 验收明细表格

增加两列：

| 列 | 说明 |
|---|---|
| 取样数量 | 可编辑数字输入 |
| 入库数量 | 只读展示服务端返回值 |

建议在取样数量输入后实时显示预计入库数量，方便验收员核对。

### 2.2 新增 / 编辑验收单

接口不变：

- 新增：`POST /api/acceptance/withDetails`
- 批量更新明细：`PUT /api/acceptance/detail`

新增请求示例：

```json
{
  "acceptance": { "sourceType": "采购入库", "relatedOrder": "DD-20260723-001" },
  "details": [
    {
      "materialCode": "Y0084",
      "materialName": "甘草",
      "materialCategory": "原料",
      "unitName": "kg",
      "standardDosage": 0.021,
      "quantity": 0.42,
      "actualArrivalQty": 0.40,
      "samplingQty": 0.02,
      "unitPrice": 30,
      "batchNumber": "HG20260723",
      "expiryDate": "2027-07-23"
    }
  ]
}
```

批量更新明细示例：

```json
[
  { "detailId": 1, "batchNumber": "HG20260723", "unitPrice": 30 },
  { "detailId": 2, "actualArrivalQty": 0.40, "samplingQty": 0.02, "batchNumber": "HG20260724" }
]
```

表单交互要求：

1. 取样数量默认 0，允许为空（后端按 0 处理）。
2. 输入时实时提示「入库数量 = 实际到货数量（未填则用采购数量）− 取样数量」。
3. 前端即时校验：
   - 取样数量 ≥ 0；
   - 取样数量 ≤ 基准数量；
   - 检验合格/入库前要求取样数量 **< 基准数量**（保证入库数量 > 0）。
4. 明细处于 `待扫码入库` / `已入库` 时，取样数量、批号、单价、仓库均不可编辑。

### 2.3 流程环节

| 环节 | 接口 | 前端注意事项 |
|---|---|---|
| 初验 | `POST /api/acceptance/{id}/inspect` | 合格不强制校验取样；不合格转退货时后端自动把入库数量清零 |
| 检验 | `POST /api/acceptance/{id}/quality-check` | 合格前要求批号必填，且取样数量 < 基准数量 |
| 整单入库 | `POST /api/acceptance/{id}/inbound` | 返回后主单/明细状态为 **待扫码入库**，不是已入库 |
| PDA 扫码确认 | 扫码签名确认后 | 后端回写验收单与明细为 `已入库` |
| 部分验收 | `POST /api/acceptance/{id}/partial-acceptance` | 验收子行保留取样；退货子行取样与入库数量均为 0 |
| 退货重发 | `POST /api/material-return/resend` | 新验收单明细取样数量为 0 |

状态展示不要跳过 `待扫码入库` 直接显示已入库。

## 三、常见错误提示

建议直接弹出后端返回的 `message`：

| 后端提示 | 触发场景 |
|---|---|
| `取样数量不能为负数: X` | 取样数量 < 0 |
| `取样数量不能超过入库基准数量: X` | 取样数量 > 实际到货（或采购）数量 |
| `取样数量不能等于入库基准数量，入库数量必须大于0: X` | 检验合格时取样数量等于基准数量 |
| `入库数量必须大于0，请检查取样数量: X` | 入库时数量为 0 |
| `已生成入库单或已入库的验收单不可修改/删除` | 主单处于待扫码入库/已入库 |
| `已生成入库单或已入库的明细不可删除` | 明细处于待扫码入库/已入库 |

## 四、导出

接口：`GET /api/purchase-orders/annual-statistics/export`

货物验收表由 24 列改为 **25 列**，在「到货数量」后新增「取样数量」，再到「入库数量」：

```
验收单号、来源类型、关联采购订单号、关联采购计划编号、收货单位、状态、交期、备注、
序号、物料编码、物料名称、物料分类、单位、采购数量、到货数量、取样数量、入库数量、
单价、金额、批号、有效期至、明细状态、退货原因、不合格说明、供应商
```

如果前端有导入模板或列映射配置，需要同步新增「取样数量」一列。
