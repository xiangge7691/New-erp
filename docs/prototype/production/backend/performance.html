原型说明

用于评审绩效统计的交互与口径；数据均为演示数据。

一、记录来源

每条个人绩效记录对应「人 × 生产任务 × 工序 × 生产批次」。工序批次在「实际记录」页完工后，按登记的实际时长与参与人逐人生成记录，记录来源为「系统生成」；补录记录来源为「手动添加」。绩效页不修改实际记录页的实际时长与实际数量。

二、拆分批次与绩效

工序拆分为多个生产批次时，每个批次分别登记参与人与完成数量。个人记录带出所属批次的实际时长与个人工作时间，绩效时长默认等于个人工作时间，可修正。同一班组在同一时段可以看多台设备，绩效按每人的工作时间分别计算，不按批次时长重复计入。工序粒度视图在工序下按批次分组展示参与人。

三、两种粒度

工序粒度以「任务—工序—批次—人」展开，便于核对某道工序谁参与、各计多少，支持按制剂名称、批号、生产任务号搜索；人员粒度以「人—任务—工序」归集，便于按人查询区间内的全部参与记录并导出。两个视图读同一份个人记录，任一处修改另一处同步。

四、时长与系数

工序实际时长只读；个人记录另存工作时间（参与工时），绩效时长默认等于工作时间，可修正。按系数计算时绩效工时 = 绩效时长 × 工序系数 × 人员系数；只写时长的手动记录按直接计入，绩效工时等于绩效时长。工序完工时固化当时的系数版本与人员系数快照，后续调整系数或发布新版本都不影响已生成记录。

五、修改、补录与作废

修改绩效时长须填写备注，记录修改人与时间。明细行保持精简：绩效工时标红表示该记录被修改过，点击可查看修改前后的绩效时长、修改原因、修改人与修改时间。手动添加可关联已完工工序（按系数计算）或只写时长（直接计入），绩效归属日期可回填但不晚于当天。仅手动记录可作废，作废后不计入统计与导出；将记录状态筛选切换为「仅作废（审计）」可查看作废记录。

六、展示口径

计划达成率为工序级展示指标，不折算到个人，也不受个人修改影响；计划时长或数量为 0 或缺失时显示为空。汇总属「人时」口径，多人参与会重复计入，报表已注明。

七、校验边界

原型中的保存、作废、重复补录提示、数量平衡等均为交互演示；实际校验（如工序是否已完工、绩效归属日期、重复记录、数量合计、权限）以后端接口为准，前端只负责提示与展示返回结果。

八、后端接口对接

绩效记录字段：personnelId / workOrderId / processTypeId / planId / planBatchId / executionId / performanceDate / processActualHours / workHours / performanceHours / processCoefficient / personCoefficient / coefficientVersionId / calcMode / performanceHoursTotal / completedQty / source / modifiedStatus / recordStatus；展示字段：personnelName / teamName / workOrderCode / preparationName / batchNumber / processName / planBatchName / planStartTime / planEndTime / planDurationMinutes / planQty / actualStartTime / actualEndTime / coefficientVersionNo / updatedByName。接口：GET /api/performance/records（支持 from、to、personnelId、workOrderId、teamId、source、modifiedStatus、recordStatus）、/process-view（workOrderId + teamId）、/person-view；PUT /records/{id}；POST /manual；POST /records/{id}/void?note=；GET/POST /coefficient-versions；GET /coefficient-versions/{id}（含 processItems、personItems 名称）；GET /export。source 取值为「系统生成」「手动添加」；系数发布范围 0.5–2.0，历史记录按版本快照计算。
