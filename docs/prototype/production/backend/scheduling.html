原型说明

用于评审工序排产的交互与状态规则；数据均为演示数据。

一、排产对象

以生产计划下的生产任务为入口，逐道工序维护计划时间。工序顺序与标准时长来自「制剂信息—工序信息」，计划数量默认取任务数量，设备与房间由工序信息带出，均可调整。页面同时展示生产计划号、生产任务号与制剂名称、批号，便于与生产任务页对照。

二、排产是可选的

每个生产任务可以选择排产，也可以不排产：工序填写了计划开始/结束即视为「已排产」，留空即「未排产」。未排产工序不参与排产、冲突校验与甘特图展示，也不影响生产任务流程与后续执行；排产结果仅作为生产安排的参考。页面上的排产标记（已排产/部分排产/未排产）只是「是否有计划时间」的标识，不是任务流程状态。

三、拆分多次生产（本期重点）

一道工序可以拆成多个生产批次。每个批次独立维护计划起止、计划数量、设备、房间与操作人。批次数量合计必须等于工序计划数量，否则不允许保存。拆分后甘特图按批次显示连续色块；绩效模块按批次分别登记参与人与时长。

四、顺排与调整

首道工序不早于任务计划开始时间；后续工序只需计划开始不早于紧前工序的计划开始，允许工序时段重叠，不要求晚于紧前工序结束。例如第一项 08:00–09:00、第二项 08:30–09:30 是合法排法。手工修改某道工序的计划起止只重算本工序计划用时，不联动其他工序。前道超期时后续计划不顺延，由排产员决定是否逐条调整。计划开始/结束均为选填，可随时清空恢复为未排产。

五、冲突检测

设备与房间冲突在全部已排产工序范围内比对；人员冲突按「同一人在同一时段被安排到多道工序」判断，不校验班次；工序顺序冲突按「后道工序的计划开始必须晚于紧前工序的计划开始」判断。发现冲突时标红并给出推荐可用时段；存在冲突的工序不允许保存，须逐项调整或套用推荐时段，冲突全部消除后才能保存排产。

六、班组即人员快捷分组

班组只用于排产时快捷勾选人员：选择班组会勾选其成员，之后仍可逐人增减，人员以工序上记录的名单为准。班组不作为流程、权限、资源占用或统计维度；不建班组也可以直接逐人选择。

七、页面分工

生产任务列表页顶部展示排产甘特图，点开任务进入详情页，详情页不重复展示甘特图；详情页在「生产任务详情」「变更历史」页签之外，增加「排产」「实际生产」两个页签：详情页的生产工序表只读，并标注排产/生产状态；「排产」维护计划时间、批次与人员；「实际生产」登记实际起止、实际数量与参与人，完工后锁定并生成人员绩效。两部分数据分表存放、互不回写，避免计划与实际混在一起。

八、与生产任务联动

排产结果写入独立的排产计划表和批次表（work_order_process_plan / work_order_process_plan_batch），不回写 work_order 的工序字段；实际执行仍使用 work_order_process_execution，通过 plan_id / plan_batch_id 与排产关联。生产任务详情「实际生产」页签与只读工序表上的实际起止、实际数量来自执行记录，未完工时显示为空；未排产工序的计划起止显示为「—」。

九、校验边界

原型中的保存、拆分、套用推荐时段等均为交互演示；设备/房间占用、人员重叠、工序顺序与批次数量合计等校验在前端同样生效：存在冲突时保存会被拒绝。演示数据初始无冲突；如需演示保存被拒，可在调整工序时制造时段、设备、房间或人员重叠，正式保存会打开冲突明细抽屉。

十、后端接口对接

本页字段与后端 DTO 一致：任务 workOrderId / workOrderCode / preparationName / batchNumber / batchQty / currentStatus / planStartTime / processCount / conflictCount / saved；工序 planId / processTypeId / stepOrder / planStartTime / planEndTime / planQty / roomId / equipmentId / teamId / status，以及实际对照 actualStartTime / actualEndTime / actualStatus / actualQty / executionId；批次 batches[] 含 id / batchNo / batchName / planStartTime / planEndTime / planQty / roomId / equipmentId / teamId / status，以及实际对照 actualStartTime / actualEndTime / actualStatus / actualQty / executionId / locked；冲突 conflicts[]。接口：GET /api/scheduling/tasks；GET /api/scheduling/tasks/{workOrderId}；POST /api/scheduling/tasks/{id}/auto-plan；PUT /api/scheduling/tasks/{id}/plan（草稿）；POST /api/scheduling/tasks/{id}/plan/save（正式保存，冲突返回 400 + data.conflicts）；POST /api/scheduling/plans/{planId}/split；GET /api/scheduling/gantt。计划开始/结束未填写时按「未排产」处理，不作为流程校验条件。自动顺排依赖工序模板 standard_duration，当前为空会返回 400。
