## 方案一：新增工单时自动绑定工序模板

### 核心思路

在 `WorkOrderServiceImpl.addWorkOrder()` 中，工单保存成功后：
1. 根据 `preparationId` 调用 `PreparationProcessTemplateService.findByPreparationId()` 拉取工序模板
2. 将模板列表转换为 `WorkOrderProcessExecution` 列表
3. 调用 `WorkOrderProcessExecutionService.batchSave()` 批量保存

### 字段映射关系

| 模板字段 (PreparationProcessTemplate) | 执行记录字段 (WorkOrderProcessExecution) | 映射方式 |
|---------------------------------------|----------------------------------------|----------|
| `processTypeId` | `processTypeId` | 直接复制 |
| `stepOrder` | `stepOrder` | 直接复制 |
| `keyProcessParams` | `keyProcessParams` | 直接复制 |
| `remark` | `remark` | 直接复制 |
| `standardQty` | `processQty` | 语义映射（标准量→加工量） |
| — | `workOrderId` | 由当前工单 ID 填充 |
| — | `status` | 固定设为 `"待执行"` |
| — | `isDeleted` | 固定设为 `0` |
| — | `version` | 固定设为 `1` |
| — | `roomId` | 留空（模板是文本描述，非 ID） |
| — | `equipmentId` | 留空（模板是文本描述，非 ID） |
| — | `operatorId/operatorName` | 留空（执行时填写） |
| — | `startTime/endTime` | 留空（执行时填写） |

新增私有方法 `bindProcessTemplates`:
```java
private void bindProcessTemplates(WorkOrder workOrder) {
    List<PreparationProcessTemplate> templates =
        preparationProcessTemplateService.findByPreparationId(workOrder.getPreparationId());

    if (templates == null || templates.isEmpty()) {
        return; // 该制剂没有配置工序模板，跳过
    }

    LocalDateTime now = LocalDateTime.now();
    Long currentUserId = EntityUtils.getCurrentUserId();

    List<WorkOrderProcessExecution> executions = templates.stream().map(template -> {
        WorkOrderProcessExecution exec = new WorkOrderProcessExecution();
        exec.setWorkOrderId(workOrder.getWorkOrderId());
        exec.setProcessTypeId(template.getProcessTypeId());
        exec.setStepOrder(template.getStepOrder());
        exec.setProcessQty(template.getStandardQty());
        exec.setKeyProcessParams(template.getKeyProcessParams());
        exec.setRemark(template.getRemark());
        exec.setStatus("待执行");
        exec.setIsDeleted(0);
        exec.setVersion(1);
        exec.setCreatedBy(currentUserId);
        exec.setUpdatedBy(currentUserId);
        exec.setCreatedTime(now);
        exec.setUpdatedTime(now);
        return exec;
    }).collect(Collectors.toList());

    workOrderProcessExecutionService.batchSave(workOrder.getWorkOrderId(), executions);
}
```

## 方案四：修复工单编号重复问题

### 根因

`generateWorkOrderCode()` 查询当天最大编号后生成下一个序号，但存在并发竞争窗口：
- 请求 A 查到最大编号为 `GD202607310001`，准备生成 `0002`
- 请求 B 同时查到最大编号也为 `GD202607310001`，也准备生成 `0002`
- 两者同时插入，后者触发唯一约束冲突

### 修复方案

在 `addWorkOrder()` 中增加重试逻辑：捕获 `DuplicateKeyException`，重新生成编号后重试，最多重试 3 次。

### 修改文件

**路径**: `/Users/zhouqianxiang/IdeaProjects/Erp/src/main/java/com/tonghui/erp/Service/impl/WorkOrderServiceImpl.java`

**改动**：将 `addWorkOrder()` 中的 `this.save(workOrder)` 放入重试循环：

```java
private static final int MAX_RETRY = 3;

@Override
@Transactional
public boolean addWorkOrder(WorkOrder workOrder) {
    // ... 前面的 preparationCode 填充、校验逻辑不变 ...

    for (int i = 0; i < MAX_RETRY; i++) {
        // 每次重试重新生成编号
        if (workOrder.getWorkOrderCode() == null || workOrder.getWorkOrderCode().isEmpty() || i > 0) {
            workOrder.setWorkOrderCode(generateWorkOrderCode());
        }

        try {
            boolean saved = this.save(workOrder);
            if (saved && workOrder.getPreparationId() != null) {
                bindProcessTemplates(workOrder);
            }
            return saved;
        } catch (DuplicateKeyException e) {
            if (i == MAX_RETRY - 1) {
                throw new RuntimeException("创建失败: 工单编号生成冲突，请稍后重试", e);
            }
            workOrder.setWorkOrderCode(null); // 清空，下次循环重新生成
        }
    }
    return false;
}
```

需要新增 import：`import org.springframework.dao.DuplicateKeyException;`
