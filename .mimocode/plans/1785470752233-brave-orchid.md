# 采购计划通用状态变更接口 + 清除冗余接口

## 需求

1. 新增通用状态变更接口 `PUT /api/purchase-plan/{id}/status`
2. 清除 submit、approve、reject 三个冗余接口
3. approve 的自动生成采购订单逻辑合并到 status 接口中

## 当前状态流转

```
草稿 ──submit──> 待审批 ──approve──> 已审批（自动生成采购订单）
  ^                 │
  └─────reject──────┘
       已驳回 <── 待审批
```

## 方案

### 新增接口

`PUT /api/purchase-plan/{id}/status`

请求体：
```json
{ "status": "草稿", "approvalOpinion": "同意" }
```

- 后端不做状态流转校验，直接更新为目标状态
- 当目标状态为 `"已审批"` 时，触发自动生成采购订单的逻辑（原 approve 的副作用）
- `approvalOpinion` 为可选字段

### 清除的接口

| 接口 | 原逻辑 | 处理方式 |
|------|--------|----------|
| `POST /{id}/submit` | 状态→待审批 | 删除，前端调 status 接口 |
| `POST /{id}/approve` | 状态→已审批 + 生成采购订单 | 删除，逻辑合并到 status 接口 |
| `POST /{id}/reject` | 状态→已驳回 | 删除，前端调 status 接口 |

```java
@Override
@Transactional
public boolean updateStatus(Long planId, String targetStatus, String approvalOpinion) {
    PurchasePlan plan = this.getById(planId);
    if (plan == null) {
        throw new RuntimeException("采购计划不存在");
    }

    plan.setStatus(targetStatus);
    if (approvalOpinion != null) {
        plan.setApprovalOpinion(approvalOpinion);
    }
    plan.setUpdatedTime(LocalDateTime.now());
    Long currentUserId = EntityUtils.getCurrentUserId();
    if (currentUserId != null) {
        plan.setUpdatedBy(currentUserId);
    }

    // 审批通过时，自动生成采购订单（原 approve 副作用）
    if ("已审批".equals(targetStatus)) {
        createOrderFromPlan(plan);
    }

    return this.updateById(plan);
}
```

```java
@PutMapping("/{id}/status")
public ApiResponse<Boolean> updateStatus(@PathVariable Long id, @RequestBody Map<String, String> body) {
    String status = body.get("status");
    String opinion = body.get("approvalOpinion");
    purchasePlanService.updateStatus(id, status, opinion);
    return success(true, "状态更新成功");
}
```

## 验证

1. 创建采购计划（状态为"草稿"）
2. `PUT /api/purchase-plan/{id}/status` 传 `{"status": "待审批"}` → 提交审批
3. `PUT /api/purchase-plan/{id}/status` 传 `{"status": "草稿"}` → 撤回
4. `PUT /api/purchase-plan/{id}/status` 传 `{"status": "已审批"}` → 审批通过，检查是否自动生成采购订单
