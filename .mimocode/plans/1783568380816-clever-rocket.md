# 文件管理器：业务文件与自定义文件分离

## 目录结构
```
${ERP_FILE_STORAGE_PATH}/
├── uploaded-files/       ← 业务文件（只读：仅 list/download/preview）
│   ├── 设备管理/
│   ├── 人员管理/
│   └── ...
└── custom-files/         ← 自定义文件（完整 CRUD）
    ├── 我的文档/
    └── ...
```

## 修改文件

### 1. `FileStorageConfig.java` — 新增自定义目录配置
新增属性：
```java
/** 自定义文件目录名 */
private String customDir = "custom-files";
```
新增方法：`getCustomPath()` 返回 basePath 同级的 custom-files 完整路径。

### 2. `application.yml` — 新增配置
```yaml
file:
  custom-dir: custom-files
```

### 3. `FileManagerServiceImpl.java` — 核心改造

**修改 `resolveSafePath` 方法**：
- 接收 `root` 参数（"business" 或 "custom"）
- 根据 root 类型选择不同的 basePath
- 校验路径不超出对应 root 目录

**修改 `resolveBasePath`**：
- 拆分为 `getBusinessPath()` 和 `getCustomPath()` 两个方法
- 共同的父目录 = `Paths.get(resolveBasePath()).getParent()`

**修改 `delete` 方法**：
- 增加 `root` 参数
- 如果 `root=business`，抛出异常禁止删除

**修改 `move` 方法**：
- 增加 `root` 参数
- 如果 `root=business`，抛出异常禁止移动

**修改 `rename` 方法**：
- 增加 `root` 参数
- 如果 `root=business`，抛出异常禁止重命名

**修改 `copy` 方法**：
- 增加 `root` 参数
- 如果 `root=business`，抛出异常禁止复制

**修改 `listDirectory` / `uploadFile` / `searchFiles`**：
- 增加 `root` 参数，传递给 `resolveSafePath`

### 4. `FileManagerController.java` — 接口增加 root 参数
所有接口增加 `@RequestParam(defaultValue = "custom") String root` 参数，传递给 Service 层。

### 5. `FileManagerService.java` — 接口签名更新
所有方法签名增加 `String root` 参数。

## 验证
- `./mvnw compile` 编译通过
- `GET /api/file-manager/list?root=custom` 列出自定义文件目录
- `GET /api/file-manager/list?root=business` 列出业务文件目录
- `DELETE /api/file-manager/delete?root=business&path=xxx` 返回错误：业务文件不允许删除
- `DELETE /api/file-manager/delete?root=custom&path=xxx` 正常软删除
