# 回收站功能 + 文件操作日志

## 一、数据库设计

### 1. `file_info` 表新增字段
```sql
ALTER TABLE file_info ADD COLUMN deleted_at DATETIME NULL COMMENT '删除时间（用于回收站）' AFTER is_deleted;
ALTER TABLE file_info ADD COLUMN deleted_by BIGINT NULL COMMENT '删除人ID' AFTER deleted_at;
```

### 2. 新建 `file_operation_log` 表
```sql
CREATE TABLE file_operation_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    file_id BIGINT NULL COMMENT '关联file_info表',
    file_name VARCHAR(255) NOT NULL COMMENT '文件/文件夹名称',
    file_path VARCHAR(500) NOT NULL COMMENT '文件路径',
    operation_type VARCHAR(30) NOT NULL COMMENT '操作类型：UPLOAD/DOWNLOAD/PREVIEW/CREATE_FOLDER/DELETE/RESTORE/RENAME/MOVE/COPY',
    root_type VARCHAR(20) NOT NULL COMMENT '根目录类型：business/custom',
    user_id BIGINT NOT NULL COMMENT '操作人ID',
    user_name VARCHAR(50) NULL COMMENT '操作人姓名',
    detail VARCHAR(500) NULL COMMENT '操作详情（如重命名前后的名称）',
    created_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
    INDEX idx_file_id (file_id),
    INDEX idx_user_id (user_id),
    INDEX idx_operation_type (operation_type),
    INDEX idx_created_time (created_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件操作日志表';
```

## 二、代码修改

### 1. 新建 Entity `FileOperationLog.java`
路径：`Data/Entity/FileOperationLog.java`

字段：
- `id` (Long, 主键)
- `fileId` (Long, 关联file_info)
- `fileName` (String, 文件名)
- `filePath` (String, 文件路径)
- `operationType` (String, 操作类型)
- `rootType` (String, root类型)
- `userId` (Long, 操作人)
- `userName` (String, 操作人姓名)
- `detail` (String, 操作详情)
- `createdTime` (LocalDateTime, 操作时间)

### 2. 新建 Mapper `FileOperationLogMapper.java`
路径：`Data/mapper/FileOperationLogMapper.java`

### 3. 新建 Service `FileOperationLogService.java` + `FileOperationLogServiceImpl.java`
方法：
- `void log(String fileId, String fileName, String filePath, String operationType, String rootType, String detail)` — 自动获取当前用户并记录

### 4. 修改 `FileInfo.java` — 新增字段
```java
@TableField(value = "deleted_at")
private LocalDateTime deletedAt;

@TableField(value = "deleted_by")
private Long deletedBy;
```

### 5. 修改 `FileManagerServiceImpl.java` — 核心改造

**delete 方法改造**：
- 文件：设置 `file_info.is_deleted=1, deleted_at=now(), deleted_by=userId`，不再物理删除
- 文件夹：遍历子文件，逐个软删除 file_info 记录
- 记录操作日志

**新增方法**：
- `restore(String relativePath, String root)` — 从回收站恢复
- `permanentDelete(String relativePath, String root)` — 永久删除（从回收站彻底删除）
- `listRecycleBin(String root)` — 列出回收站内容（查询 is_deleted=1 的记录）

**其他操作增加日志**：
- `uploadFile` → 记录 UPLOAD
- `downloadFile` → 记录 DOWNLOAD
- `previewFile` → 记录 PREVIEW
- `createFolder` → 记录 CREATE_FOLDER
- `rename` → 记录 RENAME（detail 记录 old→new）
- `move` → 记录 MOVE
- `copy` → 记录 COPY

### 6. 修改 `FileManagerController.java` — 新增接口
```
GET    /api/file-manager/recycle-bin          回收站列表
POST   /api/file-manager/restore              恢复文件
DELETE /api/file-manager/permanent-delete     永久删除
GET    /api/file-manager/operation-log        操作日志查询
```

### 7. 新建定时任务 `RecycleBinCleanupTask.java`
路径：`Common/Scheduled/RecycleBinCleanupTask.java`
- 每天凌晨执行
- 清理 `deleted_at` 超过30天的 file_info 记录（物理删除）
- 同时物理删除磁盘文件
