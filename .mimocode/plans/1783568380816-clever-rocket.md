# 所有删除操作改为软删除

## 一、启用 MyBatis-Plus 全局软删除

### `application.yml` — 新增配置
```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: isDeleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

**效果**：所有实体的 `removeById()`、`remove()`、`delete()` 等方法自动改为 `UPDATE ... SET is_deleted=1`，所有 `getById()`、`list()`、`page()` 等查询方法自动加 `WHERE is_deleted=0`。

## 二、修改文件清单

### 1. `application.yml` — 启用全局软删除（1处）
- 添加 `logic-delete-field`、`logic-delete-value`、`logic-not-delete-value`

### 2. `FileInfoServiceImpl.java` — 删除磁盘文件改为保留（1处）
- `deleteFile` 方法（第118-137行）：移除 `Files.delete(filePath)` 磁盘文件删除
- 仅执行 `removeById(fileId)` 软删除数据库记录

### 3. 4个手动软删除 Controller — 移除冗余手动逻辑（4处）
以下 Controller 已手动实现 `setIsDeleted(1)` + `updateById()`，全局软删除启用后 `removeById` 已自动处理，需简化：
- `TemperatureHumidityRecordController.java`（第213-226行）
- `CleanInspectionRecordController.java`（第214-226行）
- `PressureDifferenceRecordController.java`（第211-223行）
- `DisinfectionRecordController.java`（第250-262行）

改为：先 `getById` 校验存在性，再调用 `removeById(id)` 即可。

### 4. Service 层"先删后增"操作 — 保持硬删除（6处）
以下 Service 内部的删除是为了重新插入，必须保持物理删除：
- `RolePermServiceImpl.java:77` — assignPermissionsToRole
- `UserServiceImpl.java:376,407,470,473` — 角色/部门分配
- `ProductionProcessRecordServiceImpl.java:274` — batchSaveByPlanId
- `StockInServiceImpl.java:128,214` — 更新/删除入库单明细
- `StockOutServiceImpl.java:121,198` — 更新/删除出库单明细
- `ProductionUnitServiceImpl.java:158,163` — 删除发票/材料文件

**改法**：将 `service.remove(wrapper)` / `mapper.delete(wrapper)` 改为 `mapper.delete(wrapper.apply("is_deleted = 0"))`，确保物理删除生效。
