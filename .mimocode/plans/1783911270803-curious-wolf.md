# 实施计划：五个控制器 roomId 改为可选参数

## 背景
当前5个控制器中，洁净检测、消毒管理、压差记录、温湿度记录4个控制器将 `roomId` 作为 URL 路径参数（`@PathVariable`），必须传入。用户希望 roomId 变为可选：**传入时按房间过滤，不传入时返回所有记录**。

清洁记录控制器（CleaningRecordController）**已经实现了 roomId 可选**，无需修改。

## 现状分析

| 控制器 | 当前路径 | roomId方式 | 是否需要修改 |
|--------|---------|-----------|-------------|
| CleanInspectionRecordController | `/api/room/{roomId}/inspection` | `@PathVariable` (必填) | **需要** |
| DisinfectionRecordController | `/api/room/{roomId}/disinfection` | `@PathVariable` (必填) | **需要** |
| PressureDifferenceRecordController | `/api/room/{roomId}/pressure` | `@PathVariable` (必填) | **需要** |
| TemperatureHumidityRecordController | `/api/room/{roomId}/temperature-humidity` | `@PathVariable` (必填) | **需要** |
| CleaningRecordController | `/api/cleaningRecord` | `@RequestParam(required=false)` (可选) | 不需要 |

## 实施方案

参照 `CleaningRecordController` 的现有模式，将4个控制器的 **GET 查询接口** 的 roomId 从路径参数改为可选查询参数。

### 核心思路
1. **Controller 层**：将4个控制器的 `@RequestMapping` 基础路径中的 `{roomId}` 移除，GET 方法改用 `@RequestParam(required = false)` 接收 roomId
2. **查询逻辑**：roomId 为 null 时不过滤，有值时按 room_id 过滤
3. **房间名称自动填充**（关键需求）：所有 GET 查询接口（分页/不分页）必须自动填充每条记录的 `roomName` 字段。采用**批量查询**模式：先收集所有记录的 roomId，一次性查询 RoomInfo，再按 roomId 匹配填充，避免 N+1 查询问题
4. **POST/PUT/DELETE 接口**：roomId 改为请求参数（必填）或从请求体中获取

### 文件修改清单

#### 1. CleanInspectionRecordController.java
路径：`src/main/java/com/tonghui/erp/Controller/CleanInspectionRecordController.java`

修改内容：
- `@RequestMapping` 从 `/api/room/{roomId}/inspection` → `/api/cleanInspectionRecord`
- `getAll()` 方法：`@PathVariable Integer roomId` → `@RequestParam(required = false) Integer roomId`，条件查询
- `getList()` 方法：同上
- `create()` 方法：roomId 从请求体中获取（已有 `record.setRoomId(roomId)`，改为从 body 中取或加 `@RequestParam`）
- `update()`/`delete()` 方法：roomId 改为 `@RequestParam Integer roomId` 或从 record 中取
- 房间名称填充：改为批量查询方式（先查所有记录，收集 roomId，批量获取 RoomInfo）

- `reminder()` 方法：roomId 已未使用，改为可选
- POST/PUT/DELETE 方法 roomId 改为 `@RequestParam`

#### 3. PressureDifferenceRecordController.java

- Service 接口和实现类：`findByRoomId()` 方法保持不变，Controller 中直接使用 `QueryWrapper` 构建条件查询
- Entity 实体类（均有 `roomName` 字段）
- Mapper 层

### 步骤2：修改 getAll() 分页查询方法
```java
// 修改前
public ApiResponse<PagedResult<CleanInspectionRecord>> getAll(
        @PathVariable Integer roomId, ...) {
    wrapper.eq("room_id", roomId).eq("is_deleted", 0)...
    RoomInfo room = roomInfoService.getById(roomId);
    pageResult.getRecords().forEach(r -> r.setRoomName(room.getRoomName()));

// 修改后
public ApiResponse<PagedResult<CleanInspectionRecord>> getAll(
        @RequestParam(required = false) Integer roomId, ...) {
    wrapper.eq("is_deleted", 0);
    if (roomId != null) {
        wrapper.eq("room_id", roomId);
    }
    wrapper.orderByDesc("inspection_date");
    // 批量填充房间名称
    Set<Integer> roomIds = pageResult.getRecords().stream()
        .map(CleanInspectionRecord::getRoomId).collect(Collectors.toSet());
    if (!roomIds.isEmpty()) {
        Map<Integer, RoomInfo> roomMap = roomInfoService.listByIds(roomIds).stream()
            .collect(Collectors.toMap(RoomInfo::getId, r -> r));
        pageResult.getRecords().forEach(r -> {
            RoomInfo room = roomMap.get(r.getRoomId());
            if (room != null) r.setRoomName(room.getRoomName());
        });
    }
```

## 注意事项
1. **前端联调**：API 路径变更，前端需要同步修改调用地址
2. **房间名称批量填充**：所有5个控制器的 GET 查询接口都必须自动填充 `roomName`。采用批量查询模式：先收集记录中的 roomId，一次性 `roomInfoService.listByIds(roomIds)` 查询，再按 roomId 匹配填充，避免 N+1 查询问题
3. **DisinfectionRecordController 的 reminder 接口**：当前 roomId 未在方法体中使用，保持可选
4. **保持向后兼容**：直接替换旧路径
