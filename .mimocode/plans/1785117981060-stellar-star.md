# 修复 ProductionUnit 软删除清理问题

## 问题描述

创建生产单位时，如果存在已软删除的相同编码记录，会报唯一键冲突错误：
```
Duplicate entry 'A001' for key 'production_unit.uk_prod_unit_code'
```

## 根本原因

MyBatis-Plus 全局配置了软删除（`logic-delete-field: isDeleted`），所有通过框架的查询方法都会自动添加 `is_deleted = 0` 条件。

当前 `cleanSoftDeletedByProdUnitCode` 方法使用 `baseMapper.selectOne()` 查询已软删除记录，但由于全局软删除配置，查询条件自动变成了：
```sql
WHERE prod_unit_code = 'A001' AND is_deleted = 0 AND is_deleted = 1
```
这导致永远查不到已软删除的记录。

## 解决方案

在 Mapper 中使用 `@Select` 注解直接写 SQL，绕过 MyBatis-Plus 的软删除配置。

## 修改内容

### ProductionUnitMapper.java

添加两个方法：
```java
@Select("SELECT prod_unit_id FROM production_unit WHERE prod_unit_code = #{prodUnitCode} AND is_deleted = 1 LIMIT 1")
Long selectDeletedIdByCode(@Param("prodUnitCode") String prodUnitCode);

@Delete("DELETE FROM stock WHERE prod_unit_id = #{prodUnitId}")
int physicalDeleteStockByProdUnitId(@Param("prodUnitId") Long prodUnitId);

@Delete("DELETE FROM production_unit WHERE prod_unit_id = #{prodUnitId} AND is_deleted = 1")
int physicalDeleteByProdUnitId(@Param("prodUnitId") Long prodUnitId);
```

### ProductionUnitServiceImpl.java

修改 `cleanSoftDeletedByProdUnitCode` 方法：
```java
public int cleanSoftDeletedByProdUnitCode(String prodUnitCode) {
    Long deletedId = baseMapper.selectDeletedIdByCode(prodUnitCode);
    if (deletedId == null) {
        return 0;
    }
    // 先物理删除子表关联记录
    baseMapper.physicalDeleteStockByProdUnitId(deletedId);
    // 再物理删除 production_unit 记录
    return baseMapper.physicalDeleteByProdUnitId(deletedId);
}
```

## 验证

1. `./mvnw compile` 编译通过
2. 创建一个生产单位（如 A001）
3. 软删除该生产单位
4. 再次创建相同编码（A001）的生产单位
5. 验证创建成功
