# 删除生产单位材料文件表方案

## 背景

当前系统有两套文件管理机制：
1. **ProdUnitMaterialFile** - 生产单位专属，Base64存数据库
2. **FileInfo** - 统一文件信息表，文件存磁盘

用户要求删除 ProdUnitMaterialFile，统一使用 FileInfo。

## 删除范围

### 需要删除的文件（6个）

| 文件 | 说明 |
|------|------|
| `Data/Entity/ProdUnitMaterialFile.java` | 实体类 |
| `Data/mapper/ProdUnitMaterialFileMapper.java` | Mapper接口 |
| `Data/mapper/ProdUnitMaterialFileMapper.xml` | Mapper XML |
| `Service/ProdUnitMaterialFileService.java` | Service接口 |
| `Service/impl/ProdUnitMaterialFileServiceImpl.java` | Service实现 |

### 需要修改的文件（3个）

| 文件 | 修改内容 |
|------|----------|
| `Service/impl/ProductionUnitServiceImpl.java` | 删除材料文件相关方法（8个），移除依赖注入 |
| `Controller/ProductionUnitController.java` | 删除材料文件相关接口（4个） |
| `Common/Dto/System/ProductionUnitWithDetailsDto.java` | 删除 materialFiles 字段 |

### ProductionUnitController 需要删除的接口（4个）

| 接口 | 方法 | 路径 |
|------|------|------|
| 添加材料文件 | POST | `/api/production_unit/{id}/material-file` |
| 获取材料文件列表 | GET | `/api/production_unit/{id}/material-files` |
| 下载材料文件 | GET | `/api/production_unit/material-file/{materialId}` |
| 删除材料文件 | DELETE | `/api/production_unit/material-file/{materialId}` |

### ProductionUnitServiceImpl 需要删除的方法（8个）

1. `deleteProductionUnit()` 中的级联删除材料文件逻辑
2. `searchWithDetails()` 中的批量查询材料文件逻辑
3. `addProdUnitMaterialFile(ProdUnitMaterialFile)` - 直接传实体新增
4. `addProdUnitMaterialFile(Long, String, String, String, Long, String)` - 通过属性参数新增
5. `addProdUnitMaterialFile(Long, String, MultipartFile, String)` - 通过MultipartFile上传新增
6. `getProdUnitMaterialFileById(Long)` - 根据ID查询
7. `getProdUnitMaterialFiles(Long)` - 查询某生产单位的所有材料文件
8. `deleteProdUnitMaterialFile(Long)` - 删除单个材料文件
9. `getFileInputStream(String)` - Base64解码为输入流

## SQL 修改脚本

```sql
-- 删除生产单位材料文件表
DROP TABLE IF EXISTS `prod_unit_material_file`;
```

## 验证

1. `./mvnw compile` 编译通过
2. 测试生产单位的增删改查功能正常
3. 测试生产单位的带子表查询功能正常（不再返回 materialFiles）
