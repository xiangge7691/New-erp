# 计划：为所有「编号+标题/名字」实体的查询接口添加 keyword 虚拟关键字

## 目标

为所有同时具备「编号 + 标题/名字」字段的业务实体，在其 `/search` 和 `/search-with-details` 查询接口添加 **keyword** 关键字模糊查询参数（虚拟参数）：

- **不新增数据库字段、不新增实体字段**，仅作为 Controller 的 `@RequestParam(required = false) String keyword`
- keyword 同时模糊匹配：**编号列 + 标题/名字列 + 制剂名称等关联名称列**（若实体存在）
- 参照已实现的标准模式（ProductionPlanServiceImpl.java:107-110）：

```java
if (StringUtils.hasText(keyword)) {
    wrapper.and(w -> w.like("plan_number", keyword).or().like("plan_name", keyword));
}
```

## 已具备 keyword 的实体（不改）

ProductionPlan、PurchasePlan（根列表）、Preparation（/search）、Position、PersonnelFile、EquipmentMaintenance —— 均已在改造清单之外，不要重复修改。

## 通用改造模式（每个实体套用）

1. **Controller**：`/search` 与 `/search-with-details` 方法签名加 `@RequestParam(required = false) String keyword`，同步更新 Javadoc 示例请求（`?keyword=xxx`）；调用 Service 时透传 keyword。
2. **Service 接口**：对应方法签名加 `String keyword` 参数。
3. **ServiceImpl**：在 QueryWrapper（或 lambdaQuery）创建之后、其他字段条件之前插入标准 keyword 块。
4. **search-with-details 复用底层 query 方法**：底层 query 方法加 keyword，`searchWithDetails` 加 keyword 并透传。
5. **其他调用点**（`getAllData`、`/enabled`、`getEnabled*`、根列表等）调用签名变化的方法时传 `null`，否则编译失败。
6. 所有新增 Javadoc 用中文，遵循项目 region/注释规范。

## 特殊差异提醒

- **RoomInfo / ProcessType**：方法参数不是实体，keyword 作为额外 String 参数插入；RoomInfo 用 lambdaQuery 写法
- **Material / Stock**：存在 query 方法重载，Material 两个重载独立实现都要加；Stock 三参是委托，透传即可
- **ProductionUnit**：三参重载委托七参，三参签名可不动
- **Equipment**：`fixed_asset_code` 现有 eq 匹配，keyword 块内改用 like
- **WorkOrder / TrainingRecord / VerificationRecord**：无 `/search-with-details`，只改 `/search` 一条链

## 不做的事

- 不新增实体字段、不新增数据库列
- 不改动已支持 keyword 的实体（ProductionPlan 等）
- 不改无独立 Controller 的明细表（StockInDetail 等）、需 JOIN 的 exist=false 字段实体（PlanStatusLog、环境监控记录等）
