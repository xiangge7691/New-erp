# Dashboard 待办事项接口问题修复方案

## 一、问题清单

### 1. 设备维保提醒
| 问题 | 说明 |
|------|------|
| 缺少 `is_deleted = 0` | 已删除的维保记录也会被查出来 |
| 不包含已超期记录 | `findUpcomingMaintenance` 只查 `>= today`，已超期的不会提醒 |

### 2. 待入库
| 问题 | 说明 |
|------|------|
| 缺少 `is_deleted = 0` | 已删除的入库单也会被查出来 |
| content 描述错误 | 状态是 "草稿"，但 content 说 "已完成检验，待入库"，语义矛盾 |

### 3. 待确认
| 问题 | 说明 |
|------|------|
| 缺少 `is_deleted = 0` | 已删除的入库单也会被查出来 |
| status 与 todoType 矛盾 | status="已确认" 但 todoType="待确认"，逻辑混乱 |

### 4. 人员管理
| 问题 | 说明 |
|------|------|
| 不区分已过期/即将到期 | content 统一说 "还有X天到期"，已过期的应该说 "已过期X天" |

### 5. 环境管理（消毒）
| 问题 | 说明 |
|------|------|
| 不包含已超期记录 | `findUpcomingDisinfection` 只查 `>= today`，已超期的不会提醒 |

---

## 二、修复方案

### 文件 1: `DashboardController.java`

**设备维保**（第 231 行）：
- 改调新方法 `findUpcomingAndOverdueMaintenance(30)`，包含已超期记录

**待入库**（第 288-302 行）：
- 添加 `is_deleted = 0`
- 修正 content：status="草稿" → "待审核" 或改为查 `in_status="待入库"`

**待确认**（第 305-320 行）：
- 添加 `is_deleted = 0`
- 修正逻辑：应查 `in_status="已到货"` 或 `in_status="待确认"`，而非 "已确认"

**人员管理**（第 329-331 行）：
- 区分已过期/即将到期：
  ```java
  if (days < 0) {
      todo.setContent(name + "健康证已过期" + Math.abs(days) + "天");
  } else {
      todo.setContent(name + "健康证还有" + days + "天到期");
  }
  ```

### 文件 2: `EquipmentMaintenanceServiceImpl.java`
- `findUpcomingMaintenance` 改为 `findUpcomingAndOverdueMaintenance`
- 查询条件：`next_disinfection_date >= today - days`（包含已超期）

### 文件 3: `DisinfectionRecordServiceImpl.java`
- `findUpcomingDisinfection` 改为 `findUpcomingAndOverdueDisinfection`
- 查询条件：`next_disinfection_date >= today - days`（包含已超期）
