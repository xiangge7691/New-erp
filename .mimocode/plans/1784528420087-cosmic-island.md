# 验证管理模块实现计划

## 需求概述

6个验证类别（设备确认/厂房验证/工艺验证/清洁验证/设施验证/检验方法验证）共享相同字段模板，使用一张表 `verification_record` + `category` 字段区分类型。

## 数据库设计

### 表结构 `verification_record`

```sql
CREATE TABLE IF NOT EXISTS `verification_record` (
    `id` BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    `category` VARCHAR(20) NOT NULL COMMENT '验证类别（equipment/building/process/cleaning/facility/method）',
    `verification_no` VARCHAR(50) NOT NULL COMMENT '验证编号',
    `verification_name` VARCHAR(200) NOT NULL COMMENT '验证名称',
    `related_object` VARCHAR(100) NOT NULL COMMENT '关联对象',
    `execute_date` DATE NOT NULL COMMENT '执行日期',
    `next_verify_date` DATE COMMENT '下次验证日期',
    `executor` VARCHAR(50) COMMENT '执行人',
    `auditor` VARCHAR(50) COMMENT '审核人',
    `remark` VARCHAR(500) COMMENT '备注',
    `reminder_status` INT DEFAULT 0 COMMENT '预警状态（0未处理/1已处理/2不再提醒）',
    `is_deleted` INT DEFAULT 0 COMMENT '是否已删除（0否1是）',
    `version` INT DEFAULT 1 COMMENT '乐观锁版本号',
    `created_by` BIGINT COMMENT '创建人ID',
    `updated_by` BIGINT COMMENT '更新人ID',
    `created_time` DATETIME COMMENT '创建时间',
    `updated_time` DATETIME COMMENT '更新时间',
    UNIQUE KEY `uk_verification_no` (`verification_no`),
    INDEX `idx_category` (`category`),
    INDEX `idx_execute_date` (`execute_date`),
    INDEX `idx_next_verify_date` (`next_verify_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='验证记录表';
```

附件通过现有 `file_info` 表关联（business_id = verification_record.id, business_type = "VERIFICATION"）。

## 需要创建的文件

### 1. 实体类
**文件**: `src/main/java/com/tonghui/erp/Data/Entity/VerificationRecord.java`

继承 `AuditEntity`，字段对应表结构。`category` 字段使用常量类定义枚举值。

### 2. 常量类
**文件**: `src/main/java/com/tonghui/erp/Common/Constants/VerificationCategory.java`

定义6个验证类别的常量：
```java
public class VerificationCategory {
    public static final String EQUIPMENT = "equipment";       // 设备确认
    public static final String BUILDING = "building";         // 厂房验证
    public static final String PROCESS = "process";           // 工艺验证
    public static final String CLEANING = "cleaning";         // 清洁验证
    public static final String FACILITY = "facility";         // 设施验证
    public static final String METHOD = "method";             // 检验方法验证
}
```

### 3. Mapper 接口
**文件**: `src/main/java/com/tonghui/erp/Data/mapper/VerificationRecordMapper.java`

继承 `BaseMapper<VerificationRecord>`，包含：
- `selectExpiringVerifications(Date warningDate)` — 到期提醒查询

### 4. Service 接口
**文件**: `src/main/java/com/tonghui/erp/Service/VerificationRecordService.java`

方法：
- `addVerificationRecord(VerificationRecord)` — 新增
- `updateVerificationRecord(VerificationRecord)` — 更新
- `deleteVerificationRecord(Long id)` — 软删除
- `getVerificationRecordById(Long id)` — 按ID查询
- `getVerificationRecordList(int pageIndex, int pageSize)` — 分页查询
- `queryVerificationRecords(VerificationRecord, int pageIndex, int pageSize)` — 高级查询（支持 category 筛选）
- `getExpiringVerifications(int days)` — 到期提醒
- `updateReminderStatus(Long id, Integer status)` — 更新预警状态

### 5. Service 实现
**文件**: `src/main/java/com/tonghui/erp/Service/impl/VerificationRecordServiceImpl.java`

### 6. Controller
**文件**: `src/main/java/com/tonghui/erp/Controller/VerificationRecordController.java`

继承 `BaseCrudController<VerificationRecord, VerificationRecord, Long>`

接口：
- 标准 CRUD（继承基类）
- `GET /api/verification-record/search` — 高级查询（支持 category、verificationNo、verificationName、relatedObject 筛选）
- `GET /api/verification-record/warning?days=30` — 到期提醒
- `PUT /api/verification-record/{id}/reminder-status` — 更新预警状态

前端通过 `category` 参数区分6个页面，例如：
- `GET /api/verification-record/search?category=equipment&pageIndex=1&pageSize=20` — 设备确认列表
- `GET /api/verification-record/search?category=building&pageIndex=1&pageSize=20` — 厂房验证列表

## 验证方案

| 验证类别 | category值 | 关联对象来源 | 编号前缀 |
|---------|-----------|------------|---------|
| 设备确认 | equipment | 从设备信息下拉选择 | EQ |
| 厂房验证 | building | 从房屋信息下拉选择 | BLD |
| 工艺验证 | process | 手动输入 | PRO |
| 清洁验证 | cleaning | 从设备信息下拉选择 | CLN |
| 设施验证 | facility | 手动输入 | FAC |
| 检验方法验证 | method | 手动输入 | MET |

4. `GET /api/verification-record/warning?days=30` 查询到期提醒
