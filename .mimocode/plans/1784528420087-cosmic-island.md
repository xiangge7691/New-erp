# 供应商审核到期提醒优化计划

## 需求分析

用户提出三个改进点：

1. **下次审核时间是否可以手填** — 当前代码已支持手填（前端传入 `nextAuditDate` 时不触发自动计算），**无需代码改动**，仅需确认前端已支持该字段输入。

2. **过期记录也应显示在到期提醒** — 当前SQL只查 `next_audit_date BETWEEN today AND today+N`，已过期的记录（`next_audit_date < today`）不会返回。需要修改为 `<= warningDate`，包含已过期记录。

3. **按供应商筛选最新一条** — 当前返回所有到期记录，同一供应商可能有多条。需要按 `supplier_id` 分组，每个供应商只返回一条最新的审核记录。

## 修改文件清单

### 1. `SupplierAuditMapper.java` — 修改到期查询SQL
**文件**: `src/main/java/com/tonghui/erp/Data/mapper/SupplierAuditMapper.java`

将 `selectExpiringAudits` 方法的 `@Select` 注解SQL从：
```sql
SELECT * FROM supplier_audit
WHERE next_audit_date BETWEEN #{today} AND #{warningDate}
AND is_deleted = 0
ORDER BY next_audit_date ASC
```

改为（使用 MySQL 8.0 窗口函数按供应商分组取下次审核日期最新的一条）：
```sql
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY supplier_id ORDER BY next_audit_date DESC) as rn
    FROM supplier_audit
    WHERE next_audit_date <= #{warningDate}
    AND is_deleted = 0
) ranked
WHERE rn = 1
ORDER BY next_audit_date ASC
```

**改动说明**：
- `BETWEEN #{today} AND #{warningDate}` → `<= #{warningDate}`：去掉下界，包含已过期记录
- 使用 `ROW_NUMBER() OVER (PARTITION BY supplier_id ORDER BY next_audit_date DESC)` 按供应商分组，取下次审核日期最新的一条
- 外层筛选 `rn = 1` 只保留每个供应商的最新记录
- 保留 `ORDER BY next_audit_date ASC` 按到期时间升序排列

### 2. `SupplierAuditServiceImpl.java` — 移除 `today` 参数传递
**文件**: `src/main/java/com/tonghui/erp/Service/impl/SupplierAuditServiceImpl.java`

`getExpiringAudits` 方法中不再需要 `today` 参数（SQL不再使用），可以简化为只传 `warningDate`。

### 3. `SupplierAuditMapper.java` — 更新方法签名
**文件**: `src/main/java/com/tonghui/erp/Data/mapper/SupplierAuditMapper.java`

`selectExpiringAudits` 方法参数从 `(Date today, Date warningDate)` 改为 `(Date warningDate)`，移除不再使用的 `today` 参数。

## 不需要修改的文件

- **`SupplierAudit.java`** — 实体类，`nextAuditDate` 字段已是 `Date` 类型，支持手填
- **`SupplierAuditController.java`** — 控制器调用不变
- **`SupplierAuditService.java`** — 接口签名不变（`getExpiringAudits(int days)`）
