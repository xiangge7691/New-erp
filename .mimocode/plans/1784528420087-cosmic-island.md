# 供应商审核删除不生效 — 根因分析与修复计划

## 根因分析

### 删除链路
```
DELETE /api/supplier-audit/2
  → BaseCrudController.delete(2)
    → getDataById(2) → 找到记录 ✓
    → doDelete(2) → SupplierAuditController.doDelete(2)
      → supplierAuditService.deleteSupplierAudit(2)
        → this.getById(2) → 找到记录 ✓
        → supplierAudit.setIsDeleted(1) ✓
        → this.updateById(supplierAudit) → 手动更新
      → return true ← 忽略了deleteSupplierAudit的返回值
```

### 核心问题
`SupplierAuditServiceImpl.deleteSupplierAudit()` 手动调用 `setIsDeleted(1)` + `updateById()`。`updateById()` 会触发 `MetaObjectHandler.updateFill()`，自动填充 `updatedBy` 和 `updatedTime`，依赖 `SecurityContextHolder` 获取当前用户ID。如果认证链路有问题，可能导致静默失败。

而全局已配置 `logic-delete-field: isDeleted`，直接用 `removeById()` 即可自动处理软删除。

## 修改文件

### 1. `SupplierAuditServiceImpl.java:94-101`
将手动软删除改为标准 `removeById`：
```java
// 修改前
public boolean deleteSupplierAudit(Long id) {
    SupplierAudit supplierAudit = this.getById(id);
    if (supplierAudit != null) {
        supplierAudit.setIsDeleted(1);
        return this.updateById(supplierAudit);
    }
    return false;
}

// 修改后
public boolean deleteSupplierAudit(Long id) {
    return this.removeById(id);
}
```

### 2. `SupplierAuditController.java:120-128`
检查 `deleteSupplierAudit` 返回值：
```java
// 修改前
protected boolean doDelete(Long id) {
    try {
        supplierAuditService.deleteSupplierAudit(id);
        return true;
    } catch (Exception e) {
        return false;
    }
}

// 修改后
protected boolean doDelete(Long id) {
    return supplierAuditService.deleteSupplierAudit(id);
}
```
